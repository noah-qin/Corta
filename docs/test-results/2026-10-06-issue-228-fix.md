# Issue #228: six related defects repaired

Date: 2026-10-06 (Asia/Shanghai)
Original investigation base: `ab44e20`. Final verification rebased onto
main `a4883ab` (including #240/#241); not a released fix.
Investigation: [original evidence](2026-10-06-issue-228.md).

The reporter's intermittent freeze has not been matched to a specific cause.
These changes address the six independently identified failure modes.

## Changes

| Defect | Repair | Regression coverage |
| --- | --- | --- |
| A PTY read error silently abandons a live child | Record and replay a typed I/O failure outside locks; reject later input and show persistent recovery. Preserve the child and grid until explicit retry/close. | Injected read failure with a live child; reentrant callback, late subscription and input rejection. |
| A PTY write error discards input silently; keyboard ignores backpressure | Stop the writer on the first failure, discard later chunks and report recovery. Keyboard reports rejected backlog or a stopped child. | Injected first-chunk failure verifies one write attempt, discarded remainder and rejected later input; existing writer/backpressure coverage. |
| GPU feedback errors or stalled queues only log | Rebuild a faulted/stalled queue while retaining the session and renderer caches, with a three-replacement limit. Track completion independently of display callbacks; missing feedback or failed recovery stops rendering and shows recovery. | Offscreen blocked-queue replacement, cache retention and pixel checks; completion tracker coverage and bounded recovery checks. |
| RIS resets the synchronized-output episode counter | Preserve monotonically increasing episode identity across reset; a new hold receives a timeout and stale timers cannot release it. | Pure parser identity checks and real PTY tests of same-batch reset/new-hold, timeout recovery and stale timer isolation. |
| Regex matching can exceed cancellation/deadline checks | Enable engine progress callbacks and check cancellation/deadline before unwrapping a match, including nil-match progress. | Missed bounded-repetition pattern, in-flight cancellation and already-cancelled search. |
| Installed search monitor replaces a consumed nil with the original Escape | Return the active handler's optional result unchanged; only a released owner passes the event through. | Installed handler and actual posted-event dispatch close search without delivering terminal bytes; released owners pass events through. |

Runtime failure views do not take focus from an unrelated active pane. Their
retry/reconnect explanation states that recovery closes the current session
and starts a new one. Rebuild detaches the old frame loop and stops the old
session; session and queue generations reject stale callbacks.

## Scope limits

Real sleep/wake, the reporter's machine/shell and an actual failed GPU device
were not reproduced. Retry/reconnect is explicit because it replaces a live
session; the reporter's original intermittent issue remains unconfirmed.

An explicit retry closes the current child and replaces its session. Automatic
queue replacement preserves the child, grid and caches. Recovery is bounded;
these checks do not establish that a truly failed GPU device recovers, or that
the reporter's machine and shell reproduce the same failure.
