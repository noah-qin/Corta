# 0.1.1 engineering audit — 2026-09-05

Companion to [the accepted quality programme](V0.1.1-QUALITY-PLAN.md).
Adoption decisions are updated by the maintainer's subsequent
[modern technology direction](TECHNOLOGY-DIRECTION.md): actively implement and
evaluate new capabilities, not just defer them as optional experiments.
This review changed documentation only. It did not run a full Xcode build,
GUI suite, remote CI, dead-code indexer, sanitizer or competitor benchmark.
The following are implementation/audit tasks, not completed fixes.

## Additional high-priority findings

- [x] E01 **inspection, high**: Whole-window shutdown does not perform the
  cleanup used by `SplitViewController.closePane`. `AppDelegate.windowWillClose`
  removes a controller, while the reader thread strongly retains its session
  until its loop exits. Deinit cannot be relied on to call stop. Give every
  window/tab/pane close path explicit idempotent teardown of sessions, search
  tasks/monitors and notifications. Test real child PIDs and FD/thread recovery.
  - Done 2026-09-06. One explicit, idempotent `ViewController.teardown()`
    (guarded by `didTeardown`) is now the single teardown every close path
    funnels through: it closes the search bar (removing its Esc key monitor
    and invalidating any in-flight background sweep via a generation bump),
    cancels the task notifier's idle timer, removes the pane's notification
    observers, and stops the session (SIGHUP to the child's process group,
    PTY closed, reader thread exits). `SplitViewController.closePane`
    converged onto it (the duplicate inline steps are gone), and the paths
    that never reached `closePane` now call a new window-level
    `SplitViewController.teardown()`: `AppDelegate.windowWillClose` (red
    button and tab close) before dropping the controller, and
    `applicationWillTerminate` for quit.
    Changed: `Corta/ViewController.swift`, `Corta/SplitViewController.swift`,
    `Corta/AppDelegate.swift`, `Corta/ViewController+Search.swift`.
    Scope exception: `CortaTerminal/Sources/CortaTerminal/Spawn.swift` —
    `locateHelperExecutable` walks ancestors of this module's image, but
    under xcodebuild (app + test bundle both link `CortaTerminal`) the
    module is a versioned `Contents/Frameworks/*.framework` package product,
    so `corta-exec` (embedded in `Contents/MacOS`) is never an ancestor and
    no CortaTests test could spawn a real child at all; the walk now also
    checks `Contents/MacOS` when it passes a bundle's `Contents` directory.
    Tests (new file `CortaTests/PaneTeardownTests.swift`, real `zsh -l`
    children):
    `teardownTerminatesTheChildProcess` (PID reaped, `kill(pid, 0)` → ESRCH),
    `teardownIsIdempotent`, `closingASplitPaneTearsDownItsSession`,
    `windowTeardownStopsEveryPane`,
    `teardownRecoversFileDescriptorsAndThreads` (proc_pidinfo FD count and
    Mach thread count return to baseline within a deadline).
    Verified: `cd CortaTerminal && swift test` — 392 tests green;
    `xcodebuild -project Corta.xcodeproj -scheme Corta -destination
    'platform=macOS' test -only-testing:CortaTests` — 226 tests in 36
    suites green, `PaneTeardownTests` included. Remaining: none for the
    close paths themselves; note the helper-lookup fix only covers bundles
    with the helper in `Contents/MacOS` — a hypothetical release layout
    that embeds `CortaTerminal` as a dynamic framework *without* the helper
    beside the executable would still not find it.
- [x] E02 **inspection, high**: `TerminalSession.init` starts the reader before
  callers install public mutable `onOutput`/`onChildExit` callbacks. These fields
  are read from background threads without synchronization; Sendable closure
  contents do not make replacement of the closure property synchronized.
  Design configure-before-start or synchronized event delivery and replay of
  already-completed exit state. Test immediately exiting/printing children.
  - Done 2026-09-05. `init` no longer starts the reader; new idempotent
    `TerminalSession.start()` begins it, and both callbacks are stored under a
    `Mutex` (`Callbacks`). The reader records the observed `ChildExit` and a
    later-installed `onChildExit` replays it synchronously on the installing
    thread. `deinit` still cannot be relied on (the reader closure retains the
    session), so it documents that and owners must call `stop()`.
    Changed: `CortaTerminal/Sources/CortaTerminal/TerminalSession.swift`;
    `start()` added to existing callers in
    `CortaTerminal/Tests/CortaTerminalTests/TerminalSessionTests.swift` and
    `LocaleEnvironmentTests.swift`. Tests (new file
    `TerminalSessionLifecycleTests.swift`):
    `initDoesNotDrainUntilStartIsCalled`,
    `childThatExitsBeforeStartStillReportsExit`,
    `exitRecordedBeforeCallbackInstalledIsReplayed`,
    `outputWrittenBeforeStartIsSignaledAfterStart`. Verified:
    `cd CortaTerminal && swift test` — 380 tests green. Remaining: the two
    non-test callers must adopt `start()` — `Corta/ViewController.swift`
    (`startSession`, after `session.onOutput` is installed) and
    `CortaTerminal/Sources/corta-bench/main.swift` (line ~169); both are owned
    by other work items.
- [x] E03 **audit, high**: Reader batching treats a short read as evidence of
  drainage. After an exactly 64 KiB read, the next blocking read can wait with
  an unapplied batch if that read size is reachable on the PTY implementation.
  Readiness/nonblocking semantics must decide whether to drain again; cover
  exact chunk sizes with an injectable reader and a real PTY integration test.
  - Done 2026-09-05. After a full-chunk read the loop now asks a zero-timeout
    `poll` readiness check instead of looping into a blocking read, so an exact
    chunk-multiple burst is applied immediately. The read policy is an
    injectable `ReaderSource` (read + isReadable); production uses the PTY, the
    deterministic test uses a scripted in-memory source.
    Changed: `CortaTerminal/Sources/CortaTerminal/TerminalSession.swift`.
    Tests (`TerminalSessionLifecycleTests.swift`):
    `exactChunkBoundaryIsAppliedWithoutFurtherInput` (scripted exact 64 KiB
    boundary) and `chunkSizedWritesReachTheGridWithoutFurtherInput` (real PTY,
    exactly 64 KiB / 128 KiB / 64 KiB+1 followed by silence; asserts the tail
    marker reaches the grid with no further input). Verified: `swift test`
    green.
- [x] E04 **inspection**: Spawn helper error-pipe read has no deadline and no
  EINTR/partial-read protocol. UI setup calls session creation synchronously.
  Bound helper handshake time, decode the full status, clean up failed children
  and make stalled startup recoverable without freezing window creation.
  - Done 2026-09-05. The handshake read is now `Spawn.readHelperStatus`: poll
    with an absolute deadline (`helperHandshakeTimeout`, 10 s), EINTR retry,
    partial-read accumulation, and full `Int32` status decode
    (`execSucceeded` / `execFailed(code:)` / `truncated` / `timedOut` /
    `readFailed`). Every failure path kills and reaps the child
    (`reapFailedChild`), so a failed spawn no longer leaves a zombie.
    Changed: `CortaTerminal/Sources/CortaTerminal/Spawn.swift`.
    Tests (new file `SpawnHandshakeTests.swift`): `decodesAFullErrnoStatus`,
    `cleanEOFSignalsExecSuccess`, `truncatedStatusIsReported`,
    `stalledHelperHitsTheDeadlineInsteadOfBlocking`,
    `failedExecReportsTheHelpersErrno`. Verified: `swift test` green.
    Remaining: making a stalled startup recoverable *in the UI* (async session
    creation) is AppKit-side and out of this item's file scope; the library
    side now always returns within the bound.
- [x] E05 **inspection**: `presentSynchronously` manually pumps the main run
  loop for up to 0.5 s and swaps a callback temporarily. This is bounded but
  permits reentrancy. Replace startup/theme flash prevention with an explicit
  first-present state transition where practical; test close/theme/resize races.
  - Fixed 2026-09-05. `Corta/FrameScheduler.swift`: `presentSynchronously`
    replaced by an explicit state machine — `requestFirstPresent()` arms a
    stand-in `backgroundColor` (the theme's clear colour, exactly what the
    first frame's render pass clears to) and resumes the link, returning
    immediately; `notePresentedFrame()` retires the stand-in only after a
    frame was actually rendered and presented (`FirstPresentState`:
    `.idle`/`.awaitingFrame`). No run-loop pump, no callback swap, no
    reentrancy; the flash guard survives close/reattach and repeated
    theme/resize requests. `Corta/TerminalView.swift`: `drawNow()` now calls
    `requestFirstPresent()`; call sites (`SplitViewController`,
    `ViewController+Configuration`) unchanged. Regression tests:
    `CortaTests/FirstPresentTests.swift` (7 tests: stand-in colour matches
    theme clear colour; request does not service the main run loop — the
    reentrancy pin; theme-toggle collapse; close-before-first-frame;
    present-while-idle no-op; resize race at the `TerminalView` level).
    Verified: `xcodebuild -project Corta.xcodeproj -scheme Corta
    -destination 'platform=macOS' test -only-testing:CortaTests/FirstPresentTests`
    — 7/7 passed; full `-only-testing:CortaTests` run — 200 tests in 31
    suites passed. Residual: the behavioural change is that the window may be
    ordered on screen one vsync before the first real frame; the stand-in
    background covers that window. Stale comment left for its owner:
    `Corta/ViewController.swift` ~line 1006 still cites
    `presentSynchronously` in a doc-comment list of call paths (file outside
    this item's scope).
- [x] E06 **inspection**: `corta-bench` silently skips timed-out latency samples;
  later semaphore signals can also be attributed to the next input. Report
  submitted/completed/timed-out samples and correlate request/completion. Do not
  publish percentiles only over successful responses without failure counts.
  - Fixed 2026-09-05. `CortaTerminal/Sources/corta-bench/main.swift`:
    `benchmarkKeypressLatency` now pairs each request with its completion via
    a submission-time snapshot of a lock-protected completion counter — a
    round trip is recorded only once the counter advances past the snapshot,
    so a late semaphore signal from a timed-out write can never be counted
    as the next write's latency. Timeouts are counted, never sampled, and a
    0.2 s drain after each timeout resyncs late echoes; 8 consecutive
    timeouts abort the run with the counts reported. Output now prints
    `completed / submitted / timed out` beside the percentiles, with
    timed-out samples explicitly excluded. Also added the now-required
    `session.start()` (the E02 configure-before-start change had silently
    broken this benchmark: without `start()` no reader thread ever ran).
    Verified: `cd CortaTerminal && swift build` passes; `swift run
    corta-bench` prints `2000 completed / 2000 submitted / 0 timed out` next
    to p50/p95/p99/max. Residual: no unit test — `corta-bench` is an
    executable target that test bundles cannot import; verification is the
    end-to-end run. An echo arriving after the 0.2 s drain can still be
    attributed to the next request; bounded and documented in the code.
- [ ] E07 **inspection**: `Metal4Backend` forwards all rendering to QuadRenderer.
  It is a selectable placeholder, not dead code or an actual Metal 4 renderer.
  Remove/isolate the experiment or implement it behind a measured comparison;
  never count this wrapper as Metal 4 adoption.

## Toolchain and API decisions

Local `xcrun swift --version`: Apple Swift 6.3.3. Xcode uses Swift language mode
6.0; Package.swift tools version 6.2. These are different version dimensions,
not evidence that the project is compiled with an old Swift 6.0 compiler.

- [ ] A01 Preserve established AppKit/Core Text/PTY APIs where appropriate.
  `NSView`, responder-chain selectors, POSIX I/O and traditional Metal command
  submission are not obsolete merely because SwiftUI/Metal 4 exist.
- [ ] A02 `Parameters` already uses InlineArray; core uses Mutex and typed
  throws. Evaluate Span/strict-memory-safety checks in isolated parser/buffer
  boundaries. Audit unchecked Sendable and mutable unsafe globals individually.
- [ ] A03 For new background decode/search code, make actor/executor placement
  explicit and cancellation cooperative. `async` alone is not a guarantee that
  CPU work runs off the main actor. Do not move blocking PTY reads onto Swift's
  cooperative executor merely to modernize syntax.
- [ ] A04 Swift 6.3 Testing image attachments and 6.2 exit tests are useful for
  render failures and process-isolated malformed-input tests. New specialization
  or guaranteed-inlining attributes need profiling, code-size and portability
  checks, not blanket adoption.
- [ ] A05 macOS 27 WWDC26 APIs (NSTextSelectionManager, concentricity and
  interactive glass) are availability-gated experiments; retain macOS 26 path.
  Core terminal selection remains authoritative for wraps, wide cells, history
  and TUI mouse reporting. New glass must not reduce text readability.
- [ ] A06 Test pasteboard access/privacy behaviour, explicit paste intent and
  unavailable/denied reads using supported APIs; no persistent system-setting
  changes are authorized by this audit.

## CI and test architecture

Current strengths: separate core/app jobs, PR/push triggers, redundant-run
cancellation, seeded corpus replay and mutation fuzzing, release tests before
packaging, signing/notarization support and a draft release stage.

- [ ] T01 Both CI and release skip CortaUITests. Add a trusted graphical smoke
  runner/manual release gate with artifacts; never run arbitrary untrusted PR
  code on a personal/self-hosted signing machine.
- [ ] T02 Pin a tested Xcode version for the required lane; add a separate
  newer-SDK compatibility lane. Selecting newest installed Xcode makes runner
  image changes an uncontrolled variable. Test minimum supported OS separately.
- [ ] T03 Save xcresult, logs, failed pixel images, minimized fuzz inputs and
  environment metadata on failure. Ordinary CI lacks explicit result bundles
  and artifact uploads; release produces a bundle but does not upload it.
- [ ] T04 Set job/step timeouts and per-process fuzz limits; keep deterministic
  regression seeds on PRs, multiple rotating seeds and ASan/TSan jobs nightly.
  A fixed seed alone is not expanding coverage indefinitely.
- [ ] T05 Add negative/out-of-range parser tests, write backpressure/cancellation,
  startup/exit races, full-window teardown, image-budget, menu interaction and
  Services-through-PTY safety tests. Services callback invocation alone doesn't
  test sanitization or child-visible bytes.
- [ ] T06 The binary-archive reload path is bypassed under XCTest, so the current
  second-renderer test cannot prove production cache loading. Add an isolated
  real-app cold/warm/corrupt-cache smoke test with test-owned cache storage.
- [ ] T07 Parallelize pure core tests; serialize suites mutating shared AppKit
  state. Suite serialization does not globally serialize all other suites.
  Isolate configuration, clipboard, restoration and cache fixtures from users.
  - Observed 2026-09-06 (reproduced): a full parallel `CortaTests` run crashed
    the test runner in `ColorEmojiRenderTests.render` with a zero-height
    `MTLTextureDescriptor` (4 crash reports, 11:07–15:15; same stack each
    time — Metal's `validateWithDevice:` aborting). Both suites involved pass
    in isolation; the `.serialized` trait did not prevent cross-suite
    concurrency in the same process. Pre-existing flake, not caused by the
    day's S02/S03/S07 fixes. Fix belongs here: serialize the Metal/atlas
    suites against each other and harden the test helper against zero
    metrics (guard + `Issue.record` instead of a trap).
- [ ] T08 Use branch/behaviour coverage and mutation checks for critical
  validators, plus input chunk-boundary invariants, golden-grid differentials
  and real-client recordings. Test counts alone are not coverage evidence.
- [ ] T09 Separate PR correctness from dedicated hardware performance trends;
  do not gate shared runners on a tight millisecond threshold. Cache dependencies
  by OS/architecture/Xcode/lockfile; benchmark cache savings before caching large
  DerivedData. Retain periodic clean builds and unchanged required job names.
- [ ] T10 Explicit least-privilege workflow permissions and SHA-pinned Actions;
  pass dispatch/tag strings through env and validate tags instead of templating
  them into shell code. Signing credentials need always-run cleanup. Dispatch
  inputs are maintainer-controlled, not an established public-PR exploit.
- [ ] T11 Official releases should fail closed when signing inputs are missing;
  distinguish unsigned development artifacts. Preserve draft review. Unify
  script/workflow packaging checks and verify tag, bundle/core version, minimum
  OS and final archive/appcast hashes. Release notes currently say 26.5 while
  project deployment target is 26.0.
