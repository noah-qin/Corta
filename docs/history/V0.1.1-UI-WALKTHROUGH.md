# Live UI walkthrough — 2026-09-05

Inspected the maintainer-launched Corta build with native computer-use tools.
No application preferences were changed. This was an English, dark-appearance
walkthrough, not a full UI/IME/accessibility or performance certification.
The tool reported the application bundle changed during the walkthrough; state
was refreshed before proceeding. No exact build hash was established.

## Observed working

- The main window presents a restrained title bar and terminal content.
- Find opens, receives a pasted query, reports 2/2 matches in the sample and
  highlights matches. It also fits inside an approximately half-width pane.
- Split Pane Right produces two panes and focuses the newly created pane.
- Closing the new empty pane restores the original single-pane layout.
- The command palette opens from View, displays grouped actions and shortcuts,
  and filters `split` into the two split actions.
- Settings Appearance/Terminal/General pages open and switch correctly.
- Edit has no visible spelling, substitution or Find and Replace template
  items in the inspected terminal-focus state; Undo/Redo/Cut/Delete are disabled.
- A harmless printf sample emitted Chinese, accented text, a ZWJ emoji sequence
  and green ANSI text. Output is present in both the AX tree and screen;
  exact emoji glyph shape/width and IME candidate placement remain unverified.

## UI work to retain

- [x] UI01 **Observed layout defect**: Terminal Settings clips the long label
  "Let terminal programs write to the clipboard" at the end. AX retains the
  full label but the screenshot does not. Use a complete wrapping label or a
  shorter label with explanatory text; test longer localizations.
  Done 2026-09-06 (quality plan item 6): the row carries the short label
  "Allow clipboard writes" over a wrapping explanation line, and the row grows
  to fit a two-line label (`Corta/SettingsWindowController.swift`). Pinned by
  `CortaTests/SettingsPageTests.swift` — "the clipboard-write row draws its
  whole label, with the explanation under it" and "every shipped localization
  of the clipboard-write label fits the two-line row", which measures every
  shipped localization against the 240 pt column clamp (the longest, German
  at 424 pt unwrapped, fits exactly two lines). Verified:
  `xcodebuild -project Corta.xcodeproj -scheme Corta -destination 'platform=macOS' test -only-testing:CortaTests/SettingsPageTests`
  — all pass. Limit: a future translation needing three lines at 240 pt will
  fail the sweep and must be shortened, or the two-line cap revisited.
- [x] UI02 **Readability improvement**: Find's translucent background allows
  underlying terminal text to compete visually with the query and controls.
  Improve the glass treatment/contrast while retaining native appearance;
  verify dark/light, dense output and reduced-transparency modes.
  Done 2026-09-06: the Find bar's glass now carries a tint —
  `.windowBackgroundColor` at 0.55 alpha normally, fully opaque under
  Reduce Transparency, which means "background must not show through", not
  "less alpha" — and the match count moved from tertiary to secondary
  label colour (`Corta/ViewController+Search.swift`). The native glass
  material, shape and position are unchanged. Verified: compiles and runs
  in the 2026-09-06 `xcodebuild -project Corta.xcodeproj -scheme Corta
  -destination 'platform=macOS' test` run (TEST SUCCEEDED); dark/light
  adaptation comes from the dynamic colour and the reduced-transparency
  branch is explicit in code. Limits: no automated test pins the
  tint/alpha (they are appearance-dynamic), and the dark/light,
  dense-output and reduced-transparency checks are code-path inspection,
  not a fresh visual pass.
- [x] UI03 **Visual preference**: The active pane's full blue outline is strong
  relative to the quiet content. Evaluate a subtler treatment while preserving
  obvious keyboard focus and increased-contrast accessibility.
  Done 2026-09-06: the focus ring is now the user's accent colour pulled
  back to half alpha (`focusRingAlpha` = 0.5) at the existing 1 pt hairline
  — it still marks the pane that owns the keyboard, but no longer reads as
  the loudest element on screen; under Increase Contrast the full-strength
  accent returns and the ring gains a point of width
  (`Corta/ViewController.swift` — `focusRingColor`, applied in the focus
  highlight update and at ring creation). The faint background lift and the
  unfocused-pane dim are unchanged. Verified: same xcodebuild run as UI02
  (TEST SUCCEEDED). Limits: no automated test pins the alpha; "subtler but
  still obvious" was judged by code review against this walkthrough's
  complaint, not by a renewed visual comparison.
- [x] UI04 **Grouping improvement**: General Settings separates the long-task
  notification toggle/help and its "Longer than" threshold with substantial
  vertical space. Group them more clearly and verify disabled-state semantics.
  Done 2026-09-06 (quality plan item 6): measured gaps from the switch row to
  the threshold row are exactly the stack's 14 pt row spacing (the permission
  notice, when shown, is a real row in between at the same spacing — no blank
  gap). The disabled state now moves through
  `SettingsWindowController.applyThresholdState(enabled:)` — field disabled,
  label and "seconds" suffix dimmed together
  (`Corta/SettingsWindowController.swift`). Pinned by
  `CortaTests/SettingsPageTests.swift` — "the notification switch and its
  threshold sit one row spacing apart" and "the threshold row disables and
  dims with the notification switch". Verified: same xcodebuild run as UI01,
  all pass. Limit: the gap assertion reads `stack.spacing`, so a deliberate
  design change to row spacing stays valid — only an extra gap fails.
- [x] UI05 **Observed naming inconsistency**: File calls the command "New";
  the palette calls it "New Window". Align names throughout menus/palette/help.
  Done 2026-09-06 (quality plan item 6, echoes M02): File's item is now "New
  Window" — the storyboard title localizes through `command.newWindow`, the
  same key the palette and the shortcuts sheet read
  (`Corta/AppDelegate+Menus.swift`); the now-unused `menu.new` key was removed
  from `Corta/Localizable.xcstrings`. The storyboard itself is unchanged.
  Pinned by `CortaTests/MenuContentTests.swift` — "File's New names the window
  it opens, under the palette's name for the same command" (compared against
  `TerminalCommand.newWindow.title`, so it holds in every localization).
  Verified:
  `xcodebuild -project Corta.xcodeproj -scheme Corta -destination 'platform=macOS' test -only-testing:CortaTests/MenuContentTests`
  — all pass.
- [x] UI06 **Discoverability**: Shell exposes many focus and geometry commands
  in a flat list. Evaluate grouping without increasing shortcut friction.
  Done 2026-09-06: Shell now reads as create / move / resize groups — the
  storyboard's splits, then the focus moves together with the
  command-to-command jumps (both answer "go somewhere else"; the jumps used
  to sit behind the resize group, splitting the two navigation families
  apart), then the grow/shrink pairs by axis and Equalize
  (`Corta/AppDelegate+Menus.swift` `installShellMenuItems`). No key
  equivalent changed, so shortcut friction is untouched. Pinned by
  `CortaTests/MenuStructureTests.swift` — "Shell groups create, then move,
  then resize". Verified: `xcodebuild -project Corta.xcodeproj -scheme
  Corta -destination 'platform=macOS' test
  -only-testing:CortaTests/NativeIntegrationTests
  -only-testing:CortaTests/PasteTests
  -only-testing:CortaTests/MenuStructureTests` — TEST SUCCEEDED (17 tests,
  3 suites).
- [x] UI07 **Low-priority simplification**: View > Theme currently offers only
  Corta in this configuration. Reconsider a single-choice submenu while retaining
  discoverability of user-defined themes.
  Done 2026-09-06: View now carries one Theme submenu — the appearance
  choices (Follow System / Light / Dark) head the list, a separator, then
  the themes — one place for the whole light-or-dark-and-which-theme
  decision instead of two neighbouring single-choice submenus
  (`Corta/AppDelegate+Menus.swift` `installViewMenuItems` /
  `rebuildThemeMenu`). The submenu is still rebuilt as it opens, so a theme
  defined in the config file while the app runs appears immediately —
  user-defined themes keep their discoverability. Pinned by
  `CortaTests/MenuStructureTests.swift` — "View has one Theme submenu
  holding appearance, then themes" — and by the updated assertion in
  `CortaUITests/SettingsUITests.swift`
  (`testThemeAndAppearanceAreListedUnderView` now also requires the
  standalone Appearance submenu to be gone and the appearance rows to head
  Theme's list). Verified: same xcodebuild run as UI06 — TEST SUCCEEDED;
  the UI test target compiles in that build but its tests were not executed
  (graphical UI tests are the gated run tracked as audit item T01).

## Limits and cleanup

The first automation `typeText` attempt did not faithfully deliver punctuation
and non-ASCII characters; it was repeated using paste. Do not classify that
attempt as an application keyboard/IME defect. A transient palette query during
the interrupted interaction was not treated as a reproducible defect; reopening
through View showed a clean field and working filtering.

No physical IME composition, VoiceOver session, multi-monitor/fullscreen/sleep
cycle, sustained-output stress or light-mode walkthrough was performed. Search,
palette and Settings were dismissed; the added empty split was closed. Harmless
test commands/output remain in the inspected terminal history. Window-count
restoration was not asserted because same-title windows are ambiguous in the
tool's single-window observations. Clipboard-related settings were viewed only.

This walkthrough supports local UI refinement rather than a full redesign.
Track completion alongside [the quality programme](V0.1.1-QUALITY-PLAN.md) and
[modern technology direction](TECHNOLOGY-DIRECTION.md).
