# The 1.1.0 benchmark run — 2026-10-03

The release's re-measurement, taken on `main` at `ef11a93` (everything
1.1.0 ships) on the release branch. A bare `§n` below refers to
`PERFORMANCE.md`, and `PERFORMANCE.md` §5.6 keeps the current numbers.

1.1.0 is the first release whose D17 figure is a Release one (§5.8), so
its frame-CPU row is not comparable with the 1.0.x Debug column; the
comparison is against the Release figures recorded during the milestone.
The core benchmark is re-run because it is scripted and free. Live frame
CPU, launch, idle CPU, keypress → glass and energy were **not
re-measured**: they need a person at the machine or a quiet mains-powered
session, and the milestone's changes to those paths (#111–#113, the
palette lock) were each measured on their own when they landed (§5.9–§5.11
and *Follow-up performance checks*).

Reading:

- **Search and reflow** are the milestone's measured gains, and this run
  repeats them: search went from ~400 ms to ~26 ms with #137's cell scan, and
  the non-ASCII case from ~450 ms to ~27 ms with the follow-up's cell
  path; reflow halved with the follow-up's scratch reuse (the A/B in
  *Follow-up performance checks* read 92 → 48 ms).
- **Frame CPU** at 0.87 ms is inside the 0.77–0.91 ms spread the
  2026-10-02 A/B recorded for both sides on this machine, and above the
  0.55–0.74 ms of late September; the window includes the GPU's round
  trip (§5.8), and the CPU-only full rebuild (0.127–0.147 ms) is where the
  milestone left it. The claim is "no regression".
- **Keypress → grid** doubled from 0.009 to 0.018 ms p50, still far below
  anything visible; this is a PTY echo round trip on battery, and with a
  flooding neighbour the same run read 0.011 ms. Not investigated further.
- Throughput, memory and spawn are inside the 1.0.0 spread.
